# ReproPilot 产品需求文档（作品集 MVP）

## Problem

机器学习论文复现不是单纯“把代码跑通”。研究者需要理解论文条件、找到对应代码配置、建立兼容环境、诊断错误、判断补丁是否改变实验语义，并核对实际指标。现有操作通常跨论文阅读器、终端、搜索、代码编辑器和个人笔记，导致执行过程难追溯，也容易把“运行成功”误认为“复现成功”。

当前 Problem 由工程实践支持，但用户频率、耗时和严重程度仍等待五位真实参与者访谈验证。

## Target User

核心用户是具备基础 Python 或机器学习经验、手上已有论文 PDF、代码仓库和目标数据集的研究生、研究人员与 ML 工程师。他们能够理解训练指标，但不一定熟悉依赖排错、Docker、安全补丁审查或复现方法学。

本 MVP 不面向完全没有代码和命令行概念的普通读者，也不面向需要集群级实验调度的平台管理员。

## Product Goal

让用户在一个可理解、可控制的流程中完成一次缩小论文复现，并获得带证据边界的可信度判断，而不是只得到“成功/失败”一句话。

## User Journey

```text
创建任务 → 确认论文与代码范围 → 查看执行时间线
         → 处理异常或高风险审批 → 阅读可信度报告
```

## Requirements

### R1：创建任务

- 接收论文 PDF、GitHub 或本地仓库、数据集位置、Python/device 环境和运行命令；
- 用普通语言解释字段用途，并在字段旁显示可执行的修正提示；
- 缺少论文、仓库或数据集时禁止开始；
- 明确展示这是缩小复现还是与论文同范围实验。

### R2：执行前范围确认

- 展示论文声明及页码证据；
- 展示代码事实及文件、行号；
- 区分 match、mismatch 和 unknown；
- 展示未解决假设、资源限制和实验范围；
- 用户主动点击后才开始执行。

### R3：执行时间线

- 依次展示环境构建、最小运行、诊断、补丁、验证、正式实验、比较和评分；
- 状态仅使用 pending、running、verified、warning、failed 和 waiting approval；
- 同时回答“正在做什么、为什么做、证据是什么”；
- 证据面板可查看 argv、日志、Git diff、测试和 artifact ID。

### R4：高风险审批

- 数据、指标、模型和预训练权重等语义修改必须暂停；
- 展示根因、风险原因、精确 diff、语义影响和针对性测试；
- 用户可以批准或填写原因后拒绝；
- 决策绑定补丁 SHA-256，补丁变化后必须重新审查。

### R5：可信度报告

- 展示 0–100 总分、结果标签和七个证据维度；
- 展示论文值、每个种子结果、均值、标准差和差值；
- 展示已修复问题与未解决风险；
- 在分数旁明确说明“可信度分数不是模型准确率”；
- 失败、超时或拒绝也生成终止报告。

### R6：作品集原型

- 使用真实 ResNet-20/CIFAR-10 运行的去敏冻结数据；
- 清楚标记为 demo evidence，不暗示页面正在真实训练；
- 支持创建、范围确认、时间线、审批和报告的完整点击路径；
- 本地无需额外 Web 依赖即可运行。

## Priority

| 优先级 | 内容 | 理由 |
|---|---|---|
| P0 | R1–R5 的完整演示路径与证据边界 | 证明核心价值和安全控制 |
| P1 | 键盘操作、响应式桌面布局、真实 demo fixture | 支持可用性测试和求职演示 |
| P2 | 从真实运行目录动态读取数据 | 当前冻结原型验证后再做 |
| P3 | 账号、协作、远程调度 | 不属于作品集 MVP |

## Non-goals

- 多用户协作、权限后台和企业账号；
- 订阅、计费和模型用量结算；
- cloud GPU scheduling、Kubernetes 或并行训练平台；
- 通用论文聊天机器人；
- 自动获取受限数据或接受数据许可；
- 自动执行高风险语义补丁；
- 用五人探索性研究证明市场规模。

## Risks

| 风险 | 后果 | 控制方式 |
|---|---|---|
| 用户把“代码能跑”当成“论文复现成功” | 形成错误科研结论 | 范围标签、七维评分、PARTIAL 解释 |
| 用户把 80/100 当成模型准确率 | 误解产品输出 | 分数旁固定反误解文案，可用性测试验证 |
| 自动补丁改变实验语义 | 指标看似更好但不可比 | 高风险分类、SHA 绑定审批、针对性测试 |
| 演示数据被误认为实时结果 | 作品集可信度下降 | 页面和 README 同时标记冻结 demo evidence |
| 小样本访谈被过度外推 | 产品论证失真 | 展示分子/分母、范围和探索性限制 |
| 凭据或私有路径进入截图 | 安全与隐私问题 | 去敏 fixture、仓库扫描、禁止原始聊天入库 |

## Product Metrics

核心产品指标为任务完成率、理解当前状态用时、人工步骤减少量、决策正确率、报告理解率和满意度。精确定义与记录规则见 [产品指标方案](metrics-plan.md)。工程修复率和 token 成本单独报告，不能替代产品效果。

## Acceptance Criteria

- 用户可以从任务创建连续进入最终报告，所有主按钮可操作；
- 时间线中的每项结论都有可见证据；
- 高风险审批不能被跳过，错误 SHA 不能复用旧决定；
- 页面始终将 `80/100 PARTIAL` 解释为证据可信度而非模型准确率；
- 至少 4 of 5 参与者无帮助完成核心流程，且至少 4 of 5 正确解释 PARTIAL；
- 原型、截图和文档中没有凭据、私有路径或参与者身份；
- 若真实可用性测试尚未发生，作品集明确写 `Awaiting real participant responses`，不填预测结果。

## Release Boundary

本 PRD 的交付物是本地可点击作品集原型和配套产品证据，不是生产 SaaS。动态连接 CLI、真实任务管理和远程部署只有在冻结原型通过可用性验证后才评估。
